Failure type & Relevance/noise; sufficiency; consistency/conflict; provenance/freshness; integrity/adversarial corruption; uncertainty/OOD. & Code the evidence property being tested, not the paper's motivation. If a paper only says ``robustness'' without an evidence property, code the coordinate as unobtainable (\texttt{U}). & Valid comparison requires the same failure type. Same broad area but different failure property gives partial at best. \\
Evidence assumption & Benign retrieval error; benchmark-constructed stressor; naturally occurring conflict; stale or low-quality source; attacker-created evidence; privacy or extraction threat. & Natural contradiction and attacker-created contradiction are different assumptions even if the context text looks similar. For security, record corpus write access, query control, retriever visibility, generator access, insertion budget, and objective when reported. & Different assumption classes usually make a leaderboard comparison invalid; missing attacker capability caps the verdict at under-specified. \\
Intervention point & Corpus/index; retriever; reranker; context assembly/compression; generator prompting or training; verifier; system-control policy; evaluation-only artifact. & Code the first component that changes system behavior. If two methods target different components under the same failure type, compare as pipeline components, not substitutes. & Same failure but different intervention point yields partial unless the paper explicitly studies composition. \\
Metric target & Answer correctness; retrieval recall; evidence support; citation faithfulness; attack success; calibration error; selective risk/coverage; cost/latency; human preference. & Metrics are equivalent only when they measure the same target object. Answer correctness, citation support, and attack success are not interchangeable even on the same dataset. & Different metric families yield partial; conflicting target objects yield invalid for ranking by one scalar. \\
Action policy & Answer; abstain; re-retrieve; filter; verify; expose conflict; ask clarification; escalate; quarantine; recover; unreported. & The action must be explicitly stated or evaluated. It may not be inferred from task setup for a valid verdict. & Unreported action caps the verdict at under-specified. Different explicit actions under the same failure type yield partial. \\
Final verdict & Valid; partial; invalid; under-specified. & Valid = all five coordinates align under the rules above. Partial = same failure but a non-fatal mismatch in intervention, metric, or action. Invalid = assumption or objective defines a different game. Under-specified = at least one required coordinate is \texttt{U}. & The verdict is conservative: under-specification blocks valid comparison even if the papers appear topically similar. \\
